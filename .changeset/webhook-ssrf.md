Webhook delivery judges the address a destination resolves to, not only its name (GHSA-32j8-75h9-978f). `validateWebhookUrl` compared the hostname as a string, so `foo.localhost` or any name pointing at loopback passed, and delivery used global `fetch`, which followed redirects to anywhere. Delivery now goes through `createSafeFetch` (`lib/webhookTransport.ts`): it resolves the host inside the connection's own `lookup`, drops loopback, unspecified, link-local and metadata answers (including IPv4-mapped, IPv4-compatible, NAT64 and 6to4 spellings of them), connects only to an answer that passed, refuses the name when none did, and does not follow redirects. It sends `User-Agent: tapflow-webhook`, since edge WAFs refuse requests without one and `fetch` used to send its own. Registration also rejects `*.localhost`, URLs carrying credentials (which `fetch` refused and node's client would send as `Authorization`), and the literal forms the string check missed (`[::]`, `fe80::/10`, `0.0.0.0/8`, `fd00:ec2::254`). Private LAN ranges stay allowed, and a `.local` name whose answers include an `fe80::` address still reaches its LAN address.
